# Phase 11. S5 데이터·학습 필요성 가설과 조건부 명세

## 목적과 현재 상태

상태: 미실행. 기존 데이터 목록 점검과 S5의 응답 원인 연결은 구분한다. [50-D](../50-automatic-model-evaluation.md)·[60 데이터](../60-mix20k-v3-1-build.md)·[70 학습](../70-training-and-promotion.md)의 학습 필요성 가설·보정 대상·조건부 명세를 작성하며 실행은 확정하지 않는다. 데이터 추가·400건 재개·학습을 기본 다음 단계로 두지 않는다.

## 진입 조건

S3/S4 결과·앱 후보의 변경 목록·남은 오류 위치를 확보한다. S4 미실행은 숨기지 않으며 전체 진단 완료로 표시하지 않는다. 현재 R16의 실제 2K build와 별도 보정의 출처·권한을 확인한다.

## 작업 순서

<a id="data-baseline"></a>
### 데이터 단서와 한계

일반 공감 250건은 원국 미연결, 최종 답변 1,751/2,000건은 세 줄 이상, 짧은 사실 QA 축은 50건이다. 다른 축에 유사 행동이 전혀 없다고 단정하지 않지만 공감 전용 축이 연결 상태 일반 전환을 직접 대표하지는 않는다. 줄 수와 문장 수를 혼동하지 않는다.

최종 2K는 Codex 초안 2,000건·Claude 최종 판정 191건·Codex 분리 판정 1,809건의 승인 fallback이다. 전량 교차-provider 판정이라고 표현하지 않고 같은 provider의 분리 판정이라는 이유만으로 무효화하지도 않는다. 자연스러운 축약·올바른 제한 문구가 정규식에 걸려 재작성된 이력을 점검한다. 최종 데이터 전체 결함의 증거는 아니지만 좋은 요청 수행보다 검사 문법에 맞는 답이 선택됐을 가능성을 검토한다.

<a id="behavior-axes"></a>
### 행동별 대조

| 행동 | 대조와 기대 |
|---|---|
| 연결 상태 일반 대화 | 동일 일상 질문의 연결/미연결; 사주 강요 없이 수행 |
| 대화 전환 | 사주 설명 뒤 일반 공감 요청; 연결 유지·응답 주제 전환 |
| 짧은 형식 | 같은 사실에 한 단어/두 문장/자세한 설명; 요청 길이 준수 |
| 틀린 전제 | 현재 사실과 충돌하는 주장; 동조 없이 교정 |
| 정정·이력 | 이전 오답/이전 원국+최신 snapshot; 현재 사실 우선·과거 인용 구분 |
| 사실 선택 | 필요한 값 변경/무관한 값 변경; 필요한 변화에 반응·핵심 불변 |
| 불확실성 | unknown/range/미지원; 확정값과 미지원 계산 생성 금지 |

위 예시는 개발용이며 표현만 바꿔 S6의 새 확인 질문으로 재사용하지 않는다. source·허용 범위·태스크·연결 상태·split/부모 계열 중복·유사 답변·학습/serving 형식·loss mask·길이 차이와 실제 오류를 연결한다. 문자열 0건만으로 의미 커버리지 부재를 확정하지 않는다.

<a id="repair-decision"></a>
### 400건 유지·재설계·보류 제안

기존 accepted 238·판정 대기 3·초안/재작성 159와 원본 state를 보존한다. 현재 R16에 미반영이며 다른 세션 결과를 취소하지 않는다.

| 선택 | 조건과 조치 |
|---|---|
| 유지 | 보정 축이 남은 주요 오류와 일치; 계약·자동 판정 적합성 확인 후 별도 재개 |
| 재설계 | 연결 일반 대화·형식 전환 등 핵심 분포 부족; 이전 결과 보존·새 범위/build |
| 보류 | 앱/지시로 주요 오류 해소 또는 효과 근거 부족; 생성·학습하지 않음 |

무조건 2K에 400을 더해 2,400건으로 만들지 않는다. builder가 교체·보정·결합 중 무엇인지 확인하고 최종 행 수를 새 manifest에서 확정하도록 조건부 명세에 적는다. 위 선택은 제안이며 재개 승인이 아니다. [Phase 12](phase-12.md#training-decision)의 실제 제품 후보 결과를 대조한 뒤에만 [Phase 13](phase-13.md)의 실행 여부를 별도 결정한다.

<a id="failure-attribution"></a>
### 학습 선택과 최소 변경

모델 전 차단·잘못된 전달은 먼저 앱/상태를 수정한다. 기존 진단과 데이터 분포를 근거로 정상 입력의 잔여 모델 오류·표적 데이터 필요성 가설을 작성하고 Phase 12에서 대조할 반증 조건을 명시한다. 지시문으로 해결된 축에는 데이터 확대를 요구하지 않는다. R16은 비교 기준이지 자동 최종 승자가 아니다. 20K Full FT 재실행·rank 전수 탐색·3B 학습을 묶지 않는다. 여러 변수를 바꿔야 하면 묶음 개선임을 기록한다.

## 입력·산출물

응답별 오류 분류·S3/S4 결과·후보 입력 계약·고정 데이터/학습 manifest를 입력으로 삼는다. 산출물은 유지/재설계/보류 제안, 이유·반증 조건, 학습 필요성 가설·보정 대상·조건부 학습 명세다. 명세에는 출발 checkpoint·방식·rank·행 수·split·길이·학습률·epoch·예산·중단/재개·새 검증 범위를 적되 실행 확정으로 표시하지 않는다.

## 검증

분모·출처·fallback 이력·2K/400/v3 구분, 입력과 실제 serving 일치, 계열 중복, token/loss/EOS/mask 지표를 자동 대조한다. 기존 원본을 다시 승인하거나 검사기 점수를 성능으로 바꾸지 않는다. 새 생성·학습 없이 결정 자료를 작성한다.

## 종료·중단과 다음 단계

근거·한계·최소 변경 가설 또는 보류 사유와 조건부 명세가 기록되면 S5를 닫고 [Phase 12](phase-12.md)로 간다. Phase 11 완료만으로 Phase 13에 진입하지 않는다. 실제 후보 결과에서 앱·지시문으로 해소됐으면 기존 400건·학습 명세가 있어도 학습을 건너뛴다. 근거 부족은 보류 사유이지 무한 데이터 확대 사유가 아니다.

## 원문 대응

모델 문서 §6·7의 선택 조건, 전체 문서 §7의 S5와 학습 분리다. [원문·섹션 색인](../source-20260915.md)과 [행별 반영표](../requirements-20260915.json)를 따른다.
