# Phase 13. 조건부 데이터 보정·단일 학습

## 목적과 현재 상태

상태: 조건부 보류. Phase 11에서 필요성이 확인되고 별도 실행이 결정된 경우에만 진입한다. 현재 진단의 Phase 12와 새 학습의 검증 기록을 합치지 않는다. [60 데이터 정본](../60-mix20k-v3-1-build.md)·[70 학습 정본](../70-training-and-promotion.md)을 따른다.

## 진입 조건

정상 입력에서도 남은 오류, 실제 serving 계약에 맞는 보정 범위, 400건 유지/재설계/보류 결정과 새 실행 계약이 필요하다. 현재 2K·accepted 238·이전 build·checkpoint·원본 보고서는 보존한다. 2K→10K→20K 확대, v3.1 생성, Full FT·rank 전수 탐색·3B 학습은 자동 후속이 아니다.

## 작업 순서

<a id="data-contract"></a>
### 데이터 제작

- 학습 입력을 실제 사용할 입력 구조와 맞춘다. 앱이 쓰지 않는 축약 JSON만 학습하지 않는다.
- 단순 QA는 짧은 답을 포함하고 모든 답변에 세 줄·세 문장을 강제하지 않는다. 기존 최소 길이 계약은 과거 이력으로 보존한다.
- 값 포함보다 역할·정정·부정·인용을 구분한다. 검사 밖 표현을 자동 오답으로 몰지 않는다. used_fact_paths 같은 자기 선언은 보조 자료일 뿐 정답 증거가 아니다.
- fact·질문·부모 대화·변형 계열을 관리해 split 중복·유사 반복을 확인한다. consumed sealed payload는 열지 않는다.
- 승인 teacher 범위와 합성 사실만 사용한다. private 출생·응답·키를 외부로 반출하지 않는다. provider 차이와 판정 호출 분리를 정확히 기록하며 실제보다 강한 판정 절차를 주장하지 않는다.
- 보정이 교체·수정·결합 중 무엇인지 builder 계약으로 고정한다. 원본 2K+400=2,400을 가정하지 않으며 새 manifest가 최종 행 수를 소유한다.
- 새 version/build에서 source·형식·tokenizer/template·행/assistant-token 분포·EOS·mask·중복·state/grounding·길이·serialization을 검증한다. 자료·정책·코드 변경으로 과거 build를 덮어쓰지 않는다. 비학습 build는 training_promotion_allowed=false로 종료하고 학습 권한은 별도다.

<a id="training-contract"></a>
### 첫 학습의 통제

정상 입력의 지속 오류와 데이터 적합성을 근거로 소규모 단일 후보부터 비교한다. K0에서 새 adapter인지 R16 이어학습인지 실행 전에 하나를 결정하고 이유·부모·검증 범위를 고정한다. 기존 기본 모델에서 새 실험을 시작하는 정책이 기본이며 R16 이어학습은 별도 비교 계약 없이는 실행하지 않는다. KI20 이어학습은 하지 않는다.

데이터 효과 비교에서 출발 모델·rank·학습률·epoch·template·정밀도·길이를 동시에 바꾸지 않는다. 선택한 LoRA 또는 다른 단일 방식의 이유를 명시하며 자동 Full FT 전환은 없다. 변경 축·최종 행 수·split·계열 중복·실제 입력 형식을 기록한다. 전체 입력+출력을 렌더링해 잘림 없이 수용하고 작업명으로 장문 학습을 주장하지 않는다.

assistant-only mask·user/system 누출·EOS/PAD·packing 경계·truncation·중단/재개·저장·새 프로세스 reload를 확인한다. 비교하지 않는 파라미터는 고정하고 여러 변경이 필요하면 묶음 효과라고 명시한다. loss·저장 성공과 답변 평가는 분리한다. 환경·GPU·Python 헤더·native JIT·adapter/base 무결성은 기존 검증 기준을 따른다.

## 입력·산출물

Phase 11 결정문, 새 데이터/학습 계약·예산·고정 revision·평가 split을 입력으로 한다. 산출물은 비학습 후보 build, 별도 승인된 train run, reload 검증, 새로운 자동 평가 결과다. 정확한 수량·출발점·hyperparameter를 이 문서만으로 임의 결정해 실행하지 않는다.

## 검증

기존 Phase 12에서 소비한 질문은 새 모델 확인에 재사용하지 않는다. 별도 동결한 평가 범위와 기존 [공통 지표](phase-12.md#evaluation-common)를 적용한다. 원문·키·checkpoint 공개, split 누수, 근거 없는 승격을 막고 실패/미실행을 그대로 기록한다.

## 종료·중단과 다음 단계

보정·학습 필요성이 없으면 이유를 남기고 건너뛴다. 실행했다면 데이터·학습·답변 검증을 각각 닫은 뒤 [Phase 14](phase-14.md)로 연결한다. 효과 없음은 추가 규모 확대를 자동 승인하지 않는다. 품질 승격·Runtime release·운영 전환은 별개다.
