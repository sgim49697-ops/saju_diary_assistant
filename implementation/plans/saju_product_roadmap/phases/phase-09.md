# Phase 9. S4 모델 규모×정보 비교

## 목적과 현재 상태

상태: 미실행(실제 모델 비교). 2026-09-16 **실행기 구현·CPU 검증 완료**, 3B 공식 pin 등록 완료이며 가중치 다운로드·실제 GPU 비교는 범위 확인 전까지 보류한다. [구현·검증 기록](../../../history/2026-09-16-phase9-s4.md)을 따르며 Phase 9 전체 완료는 아니다. S4/50-C는 필수 진단이다. 작은 모델·데이터 중 하나로 미리 결론 내리지 않고 실제 큰 기본 모델을 비교한다. 여기서 기본 모델은 추가 사주 학습 전 Instruct다. [실험 상세](../../saju_system_context_diagnosis.md)와 [50](../50-automatic-model-evaluation.md)이 통제를 소유한다.

## 진입 조건

Phase 8B/S3 결과와 별도 실행 범위를 확인한다. S3 개선 여부, 8A 완료, Phase 10 전체 구현, R8/R32 추가 비교, 20K 재학습은 S4의 선행 조건이 아니다. S3 완료 근거는 재검증했고 아래 공식 revision·파일 hash를 등록했다. 실제 수집·GPU 실행 승인과는 구분한다.

## 작업 순서

<a id="comparison"></a>
### 모델과 2×2 조건

첫 후보는 [Kakao 공식 kanana-2-3b-instruct](https://huggingface.co/kakaocorp/kanana-2-3b-instruct)다. 공식 카드가 설명하는 1.3B의 가지치기·증류 계보 때문에 순수 파라미터 수 하나가 아닌 규모·모델 구성 차이를 비교한다. 새 가지치기나 3B 운영 전환을 제안하는 것이 아니다. 공개 benchmark를 이 프로젝트 성능으로 대체하지 않는다.

| 모델 | 추가 사주 학습 | 공통 지시 | 정보 |
|---|---|---|---|
| K0 | 없음 | P0 | C_FULL / C_MIN |
| Kanana 3B Instruct | 없음 | P0 | C_FULL / C_MIN |

48×2모델×2정보=192요청 상한이다. R16과 3B만 비교해 크기 효과를 주장하지 않는다. S3 승자 지시문을 모델별로 골라 넣지 않는다. 각 모델 공식 tokenizer/template로 의미상 같은 질문·facts·P0·동결 부모 이력을 렌더링한다. token ID·길이가 같을 필요는 없지만 어느 쪽도 입력을 잘라서는 안 된다. 각 arm이 생성한 후속 이력을 본 비교와 섞지 않는다.

<a id="registration"></a>
### 등록·preflight

정확한 ID·revision·config·weight·tokenizer/template hash, 공식 라이선스 이름/파일, loader/custom code 여부를 고정한다. KananaOpenLicense 표기는 후보 정보이지 모든 사용 방식에 대한 법적 결론이 아니다. 실제 구성·dtype·KV cache·입출력/총량·종료 token·adapter 없음·offload 여부를 기록하며 모델명 3B만으로 메모리를 계산하지 않는다.

2026-09-16 [진단 전용 등록](../../../../configs/model_versions/saju_1b_baseline/kanana-2-3b-s4-v1.0.0.json)은 `kakaocorp/kanana-2-3b-instruct`의 revision `6a5d7889964c4c590299d16e309eabab1f73f8a9`, 10파일·7,028,155,860바이트를 고정한다. 가중치는 아직 다운로드하지 않았다. 실제 3B는 `Qwen3ForCausalLM`·32 full attention·remote code 없음이며 K0의 custom/sliding 구성과 다르다. 공식 근거·라이선스 판단 범위·개별 pin은 위 등록과 구현 기록이 소유한다. 앱 registry는 그대로다.

현재 검증 환경을 일괄 최신화하지 않는다. 필요한 변경은 별도 환경에서 검증하고 기존 K0 tokenizer/loader에 이름만 바꿔 끼우지 않는다. 동일 정밀도·순차 실행·GPU 유휴·실제 여유 VRAM·다른 작업 보호·native JIT/헤더를 확인한다. 가장 긴 입력에서 삭제 없이 정상 생성·종료 가능한지 검사한다. 한쪽만 양자화·CPU offload하거나 다른 모델로 자동 대체하지 않는다. 실행 불가는 필요 조건과 함께 기록하고 대안을 별도 결정한다.

과거 응답은 최종 입력과 모델·tokenizer·template·생성 등 전체 실행 신원이 같을 때만 재사용한다. preflight도 [공유 예산](phase-07.md#budget)에 포함하고 추가 필요량은 본 비교에 숨기지 않는다.

구현된 `scripts.evaluation.system_context_s4`는 192요청 중 최대 172생성·기존 사전 차단 20을 구분한다. 각 모델 최장 적격 요청을 본 비교의 첫 두 건으로 검사하며 추가 preflight 0·공유 잔여 2는 유지한다. 양쪽에 fresh 공통 `GenerationConfig`·명시적 greedy 인자를 사용하므로 S2 K0 출력을 재사용하지 않는다. CLI의 `validate-contract`→`plan`→수집 계획 `download`는 CPU 검증했고, 이후 명시 수집→`verify-model`→실제 `execute` dry-run→GPU→`verify`는 [실행 순서](../../../history/2026-09-16-phase9-s4.md#next-execution)를 따른다.

<a id="decision"></a>
### 관찰에 따른 결정

| 결과 | 해석 |
|---|---|
| 3B가 두 정보 조건 모두 개선 | 규모·구성 변경 후보; 비용과 작은 모델 역할 축소도 검토 |
| 3B가 FULL에서만 개선 | 정보 선택·간섭 민감도 차이 가능성 |
| 둘 다 MIN에서 개선 | 필수 사실 손실 없는 projection 개선 가능성 |
| 둘 다 같은 항목 실패 | 지시·기대값·상태·검사·과제 정의 재점검 |
| 일부 개선·다른 축 악화 | 임의 가중 종합점수로 승자 선정 금지; 용도·미측정 범위 기록 |
| 자원 조건으로 미실행 | not_executed와 조건을 남기고 필수 비교 완료로 세지 않음 |

3B가 좋아도 바로 학습·운영 전환하지 않는다. 먼저 추가 학습 없는 효과를 확인한다.

## 입력·산출물

입력은 동결 48개·부모 이력·FULL/MIN·P0·등록된 두 모델이다. 산출물은 등록 manifest, preflight, 요청 대조, 조건별/paired 결과·지연·메모리·중단 사유다. private 원응답과 공개 집계를 분리한다.

## 검증

[공통 평가](phase-12.md#evaluation-common)의 분모·판정 불가·사실/형식/안전 지표를 유지한다. 메시지 의미·필수 fact·계산 권한·무삭제·cache 분리·종료·실행 신원·cold/warm 비용을 확인한다. 192는 성공 생성 수가 아니며 재사용·사전 차단·오류·미실행을 전량 대조한다.

S3의 [원응답·검사 대조](../../../history/2026-09-16-phase8-intent-s3.md#phase8b)에서 부정/개념 설명 오탐 2건과 일반 사주 언급 누락 2건을 확인했다. 유한 자동 점수를 전체 정확도로 사용하지 않는다. 검사 보완이 필요하면 S4 실행 전에 새 버전·회귀·해석 범위를 동결하고 양쪽에 동일 적용한다. 동결 S3 scorer·집계의 사후 수정이나 S3 재튜닝은 하지 않는다.

이번 구현은 별도 `role-aware-contract-v1.2.0`과 합성 회귀를 추가했고 실제 GPU 생성 0이다. 대응쌍의 판정 불가를 실패로 바꾸지 않으며 2×2 차이는 네 조건 공통 판정 가능 분모에서만 계산한다. 저장/API는 K0 슬롯의 CPU 소비 재생이지 3B 앱 통합이 아니다. 요청별 cold 비용과 warm 서비스 미측정을 구분하고 추가 호출을 자동 배정하지 않는다.

## 종료·중단과 다음 단계

비교 결과·한계·다음 선택이 있으면 해당 실험을 닫고 [Phase 10](phase-10.md)·[Phase 11](phase-11.md)에 전달한다. 필수 크기 비교가 미실행이면 후속 안전 점검은 가능하지만 전체 진단 완료·크기 가설 확인으로 표시하지 않는다. 같은 질문을 반복 튜닝하지 않는다.

## 진행 기록

- 2026-09-16 구현: S4 전용 실행기·공식 모델 pin·독립 tokenizer·scorer v1.2·안전 재개·CPU 검증을 추가했다. 실제 비교 과제는 `not_executed`, 가중치·GPU·Phase 10 이후·학습·운영 전환은 미실행이다. 최종 검증과 남은 제한은 [구현 기록](../../../history/2026-09-16-phase9-s4.md)에 모은다.

- 2026-09-16: Phase 8B의 실제 비교·미채택 결론과 검사 한계를 인계했다. S4는 여전히 미실행이며 추가 모델 호출·다운로드·학습·운영 교체를 승인하거나 수행하지 않았다.

- 2026-09-15: 후보 이름과 비교 계약을 계획에 반영했다. 실제 모델 등록·다운로드·GPU·학습은 하지 않았다.
