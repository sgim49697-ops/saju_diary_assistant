# Phase 10. 응답 모드·정보 전달·정정 흐름

## 목적과 현재 상태

상태: 미실행. 기존 v1.16은 일부 의도 수정 후보이며 일반 대화에 맞게 최종 입력을 바꾸는 단계까지 완료한 것이 아니다. 기존 세션·binding 계약 안에서 확인된 문제를 해결하는 최소 제품 후보 하나로 제한한다. [로드맵](../README.md)의 제품 후보로 진행하며 S3/S4의 동결 입력·점수는 변경하지 않는다.

## 진입 조건

Phase 8A 앱 회귀와 Phase 9 결과·제한을 확보한다. S4 미실행이면 그 상태를 유지하고 크기 결론 없이 가능한 앱 범위만 명시한다. 기존 snapshot·HMAC·binding·schema·권한과 새 후보의 변경 목록을 먼저 고정한다.

## 작업 순서

<a id="product-flow"></a>
### 최소 제품 흐름

출생정보를 한 번 입력해 원국을 확인하고, 원국/지원 날짜 질문에는 필요한 승인 facts를 사용하며, 공감·문장 작성으로 전환해도 연결 자체는 유지한다. 다시 사주를 물으면 최신 상태를 사용하고 정정·미상·미지원은 확정하지 않는다. 경량 한국어 Assistant의 이 흐름을 새 계산 기능 수보다 우선한다. 전문 상담 전체·미래 사건 적중을 목표로 주장하지 않고 일기 저장·장기 개인화·대운은 장기 범위로 남긴다. 자연스러움·장기 대화 품질을 미측정 상태에서 완료로 표시하지 않는다.

<a id="responsibilities"></a>
### 책임 분리

| 계층 | 책임과 금지 경계 |
|---|---|
| 계산기 | 승인 facts·불확실성; 상담 문장·사건 예측 아님 |
| 세션·상태 | 현재 입력·날짜·원국·revision·연결; 오래된 값의 묵시 재사용 금지 |
| 요청 판별 | 일반/사실/설명/날짜/확인 구분; 날짜 단어만으로 운세 확정 금지 |
| Context Builder | 필요한 승인 facts·이력 선택; 새 사실·미지원 계산 생성 금지 |
| 결정적 조회·표시 | 식별된 승인 필드의 정확한 값; 모델 정답률로 보고 금지 |
| LLM | 설명·공감·재작성·사실 활용; 출생정보에서 계산 추측 금지 |
| 자동 검사 | 측정 가능한 사실·상태·형식·경로; 전체 품질 인증 아님 |
| 운영 앱 | 승인 버전의 일관된 실행·저장·표시; CPU 성공만으로 서비스 교체 금지 |

계산 기능 존재, 현재 연결된 사실, 지금 질문에 필요한 사실은 각각 다른 판단이다.

<a id="response-modes"></a>
### 응답 모드

서버에는 출생정보·승인 원국·선택 날짜·revision·근거·연결 이력을 유지한다. 요청별 응답 계획과 실제 모델 입력은 별도로 구성한다. 기존 검증을 거치지 않은 임의 JSON을 새 모드라는 이유로 전달하지 않는다.

| 모드 | 필요한 정보·응답 |
|---|---|
| 일반 대화·공감·재작성 | 현재 요청·관련 일반 이력; 사주 강요 없는 생성 |
| 단순 사실 조회 | 명시적으로 유일하게 식별된 승인 필드; 프로그램 직접 응답 |
| 원국 설명 | 관련 원국 facts·불확실성; 계산 사실과 참고 해석 구분 |
| 날짜 흐름 설명 | 선택 날짜·필요한 원국/관계; 제공된 범위만 설명 |
| 의도·날짜 확인 | 확인에 필요한 상태; 부족한 항목만 질문 |
| 미지원 계산 포함 | 미지원 사유와 처리 가능한 요청 부분 분리; 계산 추측 금지 |

단순 조회의 첫 범위는 명확한 유일 필드다. 설명이 필요하면 승인된 값과 함께 LLM에 제한적으로 위임한다. 모델의 자기 선언만으로 필드 선택을 승인하지 않는다. 별도 대형 라우터·새 다단계 에이전트는 기본 의존성이 아니다.

<a id="context"></a>
### 연결 보존과 필요한 사실 선택

일반 대화에서 사주 facts를 생략해도 원국을 삭제하거나 출생정보를 다시 묻지 않는다. 사주로 돌아오면 현재 revision을 읽는다. “아까 말한 을목을 더 쉽게 설명해줘”처럼 이전 설명을 가리키면 관련 사실·이력을 유지한다. 현재 문장에 사주라는 단어가 없다고 전부 삭제하지 않는다. 이력·권한·불확실성을 포함한 allowlist와 선택 근거를 추적한다.

현재 projection 형식을 먼저 확인하며 질문별 projection 변경은 최소 제품 후보 안에 포함해 [Phase 12의 실제 통합 경로](phase-12.md#actual-app)에서 검증한다. 기존 S3/S4의 입력이나 결과에 소급 적용하지 않는다.

<a id="response-contract"></a>
### 새 제품 계약과 동결 진단 구분

단순 일진 조회에도 원국 하나를 강제하는 의무는 요청 유형에 맞게 완화할 수 있다. 새 제품 계약을 먼저 고정하고 기준선·후보에 동일 적용한다. 과거 S3/S4 기대값·응답·점수는 보존한다. 직접 사실 표시 정확도, LLM 자체 사실 활용, end-to-end 요청 성공을 따로 보고한다. 모델은 일주/일간·원국/일진을 구분하고 잘못된 전제를 현재 사실로 교정하며 짧은 답·문장 수·재작성·미상·미지원 제한을 따른다.

<a id="revision-history"></a>
### 정정·날짜 변경·이력

기존 연결 대화의 snapshot 변경 제한은 보호 기능이다. 정정·날짜 변경 때 새 검증 binding을 만들고 연결 대상 변경을 알린다. 기존 구현이 새 대화를 요구하면 우선 그 계약 안에서 UI 흐름을 개선하고 이전 snapshot을 덮어쓰지 않는다.

사용자의 일반 이야기·요청은 필요한 범위에서 유지할 수 있다. 이전 원국의 모델 설명은 현재 사실로 넣지 않고, 정정 정보는 새 revision의 근거로만 처리해 원문을 공개하지 않는다. 이전 모델 오답은 과거 발언으로 구분하고 이전 날짜 일진 설명을 새 날짜 근거로 사용하지 않는다. 첫 후보에는 대형 라우터·장기 메모리·자동 요약·세션 전면 개편·자동 일기 저장을 추가하지 않으며 선행 조건으로도 삼지 않는다. 원문이 언급한 향후 요약 오염 검사는 도입을 별도 결정할 때의 조건으로 보존한다. 과거 일상 이야기는 허용하지만 과거 일진은 [현재 날짜 정책](phase-07.md#date-policy)을 유지한다.

<a id="cpu-regression"></a>
## 검증

기존 25개 회귀를 없애지 않고 날짜 일상/운세·주제 제외 뒤 요청·혼합 날짜·문맥 후속·불필요 확인을 보완한다. 변조 binding·stale revision·미지원·다중 세션·새 프로세스·feature off를 보호한다. 일반 대화 입력에는 무관한 사주 설명을 강제하지 않고, 다시 사주로 돌아오면 최신 facts를 전달한다. partial/unknown을 exact day binding에 넣지 않는다. 기존 부모 코드·보고서·세션을 변경하지 않는다. 새로운 거대한 검사 체계를 선행 조건으로 삼지 않는다.

## 입력·산출물

입력은 승인 binding·현재 요청·필요 이력·8A/S3/S4 결과다. 산출물은 모드별 응답 계약, 선택 facts·revision·최종 입력 추적, 최소 앱 후보 하나와 변경 목록, CPU 회귀다. 실제 제품 API·버전은 구현 시 계약으로 고정하며 이 계획의 개념을 기존 API라고 부르지 않는다.

## 종료·중단과 다음 단계

후보·변경 범위와 상태/입력 회귀를 고정하고 [Phase 11](phase-11.md)에 남은 오류를 넘긴다. 실제 모델·worker·화면 확인은 [Phase 12](phase-12.md)에서 별도 수행한다. 권한·현재 사실이 불명확하면 확인/제한으로 처리하며 자동 범위 확대·배포하지 않는다.
