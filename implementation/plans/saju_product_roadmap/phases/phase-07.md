- 문단, 각 목록 항목·표 행, 코드 예시, 금지·조건부·종료 조건과 근거를 모두 반영한다. 중복은 하나의 소유 절로 연결하고 조건부 요구도 지우지 않는다. 근거 링크와 작성 당시의 미실행 진술은 출처 이력으로 보존한다.
- 기존 Phase 0~6, Runtime 10~40, KI10·KI20·R8/R16/R32 완료 이력과 report/config/release/checkpoint는 소급 수정하지 않는다. root 01·02·03은 요약, 00은 현재 상태, 50과 전체 흐름 문서는 실험 상세, Runtime은 계산 권위를 소유한다.
- 사용자 결정에 따라 후속 번호만 Phase 7~14로 확장한다. S0~S6·50-A~D와 C-A~D의 의미는 유지하며 새 승인 Gate를 만들지 않는다. 원문의 추가 Phase 금지 취지는 중복 정본·승인 체계 방지로 승계한다.

- private 출생정보·응답·키·checkpoint는 공개 문서·원격 저장소·외부 teacher로 반출하지 않는다. 계산을 LLM의 추측으로 대체하지 않고, 미지원 계산·모든 계산 관례의 확대를 이번 계획에 끼워 넣지 않는다.

<a id="calc-freeze"></a>
### 계산기의 역할과 동결

계산기는 승인된 입력·정책의 원국·일진·직접 관계 사실과 불확실성을 반환한다. 상담 문장·성격의 확정·미래 사건은 보장하지 않는다. 값이 맞는데 모델이 틀린 일간을 말하거나 일상 대화가 차단된다면 계산 정밀화가 아니라 최초 오류 계층을 확인한다.

현재 승인 값·부모 관계·원본 보고서, 한국 지역과 민간시 관례를 동결한다. 드문 경계의 잔여 불확실성을 없애기 위한 정밀화, 새 연도·대운·관계 해석, 진태양시·다른 일 경계, 대체 천문 provider는 기본 개발 과제가 아니다. 동결은 유지보수까지 영구 금지한다는 뜻이 아니다.

<a id="date-policy"></a>
### 자료·요청·연결 날짜 분리

실제 단일 일진 요청 하한은 `max(2026-09-02, 서버 KST 오늘)`이다. 예를 들어 서버 날짜가 2026-09-15이면 9월 2일 자료가 검증돼 있어도 신규 요청을 허용하지 않는다. 승인 자료 범위, 현재 도구의 허용 범위, 이미 연결된 snapshot 날짜를 각각 표시한다. 과거 일상 이야기는 정상 대화로 처리하되 과거 일진 조회는 현재 정책대로 제한한다. 과거 일기 날짜의 일진이나 출생 상한 확대가 필요하면 정책·연결 범위부터 별도 검토하며 천문 정밀화 전체를 다시 열지 않는다.

### 계속 수정할 결함

승인 범위의 잘못된 기둥·일간·일진, 양음력·윤달·시간대 정규화, 미상 시주 임의 확정, 정정 뒤 오래된 계산 재사용, 만료·변조 근거 승인, 미지원 입력의 프로세스 비정상 종료를 유지보수한다. 최소 재현·독립 기대값으로 계산/상태/전달을 분리한다. 계산값이 달라지면 기존 release를 덮어쓰지 않고 영향 검증된 새 후보·필요한 release로 처리한다.

<a id="calc-boundaries"></a>
### 허용할 절충과 금지할 절충

지원 지역·날짜·관례와 정밀도는 제한할 수 있지만 범위 밖 값을 승인 사실로 반환할 수 없다. 불확실한 경계는 한쪽으로 확정하지 않는다. 미상은 안정 사실 또는 일반 대화만 허용하고 12:00 등으로 채우지 않는다. 관계 존재를 재물·건강·직업 사건으로 확대하지 않는다. 계산 불가는 관계없는 일상 대화 중단 사유가 아니며, 검증 비용을 줄여도 미검증 범위를 통과로 표시하지 않는다. 책임지는 범위를 줄이는 것이지 정답 기준을 느슨하게 만드는 것이 아니다.

### 계산기 재개 조건

승인 범위 오답 재현, 목표 요청을 실제로 막는 제한, 공식 자료·의존성으로 깨진 전제, 명시적으로 결정된 제품 범위 중 하나가 있어야 한다. 먼저 최소 재현·독립 기대값·영향 범위, 대표 요청·최소 지원, 변경 영향·회귀, 기존 기간/관계 재사용 가능성과 비용을 각각 남긴다. 영향받는 요청 규모·심각도·사용 경험 개선을 판단하되 실제 분포가 없으면 숫자를 만들지 않는다. 특정 날짜 지원이 필요하다고 해외·대운·모든 관례를 함께 개발하지 않는다.

<a id="calc-work"></a>
### C-A~D 대응

C-A는 자료/요청 범위 분리, C-B는 계산/상태/라우팅/모델 오류 분리, C-C는 변경별 검증·재개 기준, C-D는 안정 사실·불확실성·revision·schema 호환성이다. 위 절의 문서와 유효한 기존 회귀, 새 계산 결함 없음으로 이 동결 정리를 닫는다. 모든 연도·경계·해석의 완벽함은 종료 조건이 아니다.

### 제품·모델 기준선의 해석

K0는 추가 사주 학습 전 Kanana-2 1.3B Instruct이며 사전학습 Base checkpoint가 아니다. KI10/KI20 Full FT와 R8/R16/R32의 동일 2K·1 epoch·250 step은 완료다. rank 증가는 기본 모델 크기 증가가 아니다. 현재 R16은 build-54836f556b4f·학습 길이 2,048, KI20은 20K·768이며 데이터·방식·길이가 함께 달라 단일 원인 비교가 아니다. 별도 400건은 238 accepted·3 판정 대기·159 초안/재작성 대기로 현재 adapter에 미반영이다. 기존 20K·비학습 v3 후보·현재 2K를 섞지 않는다.

재채점의 필수 사실 24문항 PASS/FAIL/UNSCORABLE은 K0 FULL 3/20/1·MIN 2/20/2, R16 11/6/7·6/10/8, KI20 0/19/5·1/19/4다. 판정 불가를 빼서 모델 순위·전체 정확도로 만들지 않는다. S2 최대 입력 1,692·이력 삭제 0, FULL/MIN 각각 48개 중 44개가 768 초과다. 768 이후를 추론에서 읽지 못한다는 뜻이 아니며 입력 무삭제도 간섭 부재 증거가 아니다. LoRA의 본질적 우월, 크기 단일 원인, 무조건 축소 효과, 검사 수정=모델 개선, 낮은 loss/재로딩=품질을 주장하지 않는다.

운영 v1.14·기본 KI20/R16 선택과 미배포 v1.16 CPU 후보를 구분한다. Phase 6은 AUTOMATED_REPAIR_REQUIRED로 단회 완료이며 절차 완료와 제품 품질 승인은 다르다. 원문 저자의 작성 시점 관측과 이번 로컬 확인도 구분한다. 최신 관측값은 00 문서에만 관리한다.

<a id="phase-order"></a>
### 의존 관계와 범위

Phase 7 → 8A(오차단)/8B(S3), 8B → 9(S4), 8A+9 → 10(최소 제품 후보) → 11(S5 가설·조건부 명세) → 12(S6·학습 실행 여부 판단)다. 13은 12의 실제 결과를 대조한 뒤 별도 승인된 데이터/학습 분기이며 불필요하면 건너뛰고, 14는 확인된 후보의 제한 운영 결정이다. S3 반복·앱 모드 전체 구현·R8/R32 추가 비교·20K 학습을 S4 선행 조건으로 추가하지 않는다. 새 학습 검증은 현재 S6 완료 기록과 섞지 않는다.

양자화·새 모델 계열·대형 라우터·장기 메모리·대운을 한 번에 추가하지 않는다. 각 단계의 최소 변경과 별도 실행 범위를 유지한다.

### 요청 예산과 실행 권한

기존 총 계획 상한 680 = S2 본 비교 288 + 보조 48 + S3 96 + S4 192 + S6 48 + 적격성 8이다. 실제 부모 342 = 생성 312 + 차단 30이며 적격성 6을 포함한다.

| 예산 항목 | 계산 | 요청 수 |
|---|---|---:|
| 전체 계획 잔여 | 680 - 342 | 338 |
| 본 비교 잔여 | S3 96 + S4 192 + S6 48 | 336 |
| 공유 적격성 잔여 | 8 - 6 | 2 |

공유 적격성 잔여는 최대 2다. 이 계산은 실행 승인이나 성공 생성 수가 아니다. 완전히 동일한 실행 신원의 응답만 검증 재사용한다. 추가 preflight·실제 통합 모델 호출은 목적·범위·예산을 사전에 별도 등록하며 기존 48·338·680 안에 숨기거나 상한을 자동 확대하지 않는다. CPU 모의 테스트는 실제 모델 호출이 아니다. Phase 13 학습 후 평가는 소비된 S6와 별개의 질문·실행 구성·예산으로 관리한다.

## 입력·산출물

입력은 원문 3개·현재 정본·실제 코드·승인된 공개 보고서다. 산출물은 원문 보존, 기계 검증 가능한 전량 반영표, Phase 7~14 문서와 기존 정본 연결, 테스트, 진행 기록이다. 새 제품 API·학습 config·실행 CLI는 추가하지 않는다.

## 검증

원문 해시·줄·섹션·모든 비어 있지 않은 행의 매핑과 유형/상태, 대상 절 존재, Phase/S 대응·예산·권한·링크를 검사한다. 활성 정본과 phases/는 재귀 검사하고 archive/는 원문 바이트·해시·반영표 대응을 검사한다. 보존 원문의 과거 표현을 현재 정책으로 바꾸지 않는다. 문서 표적과 기존 자동 정책 테스트, Ruff, 전체 unittest, diff 검사를 수행한다. 구조적 전량 검사는 의미 타당성의 자동 증명이 아니므로 원문 요구의 조건·예외·금지·종료 기준까지 담당 절과 대조한다.

## 종료·중단과 다음 단계

미연결 원문 0, 문서 충돌 해소, 테스트 통과, 한국어 커밋·push로 Phase 7을 닫는다. 원문/hash 변경·다른 세션 충돌·검증 실패는 원인을 해결하기 전 완료로 표시하지 않는다. 다음은 [Phase 8](phase-08.md)이며 자동 실행하지 않는다.

## 원문 대응

계산기 문서 전체, 모델 문서의 기준선·출처·예산, 전체 문서의 기준선·정본·공통 경계를 소유한다. 세부 행별 위치는 [반영표](../requirements-20260915.json)를 따른다.
