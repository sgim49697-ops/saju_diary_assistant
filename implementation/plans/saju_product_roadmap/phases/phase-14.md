# Phase 14. 제한 운영 결정·되돌림 검증

## 목적과 현재 상태

상태: 조건부 보류. 현재 운영 v1.14·기본 KI20와 미배포 v1.16 후보는 [00 기준선](../00-current-baseline.md)을 따른다. 이번 계획 작성으로 운영 모델·service·feature를 바꾸지 않는다.

## 진입 조건

Phase 12에서 실제 후보 경로를 확인해야 한다. Phase 13을 실행했다면 새 학습·평가까지 별도로 확인한다. 후보 하나의 코드·모델·설정·사용 범위·입력 계약·되돌림 경로가 명확하고 서비스 전환이 별도 승인돼야 한다. 조건부 분기를 건너뛴 이유도 기록한다.

## 작업 순서

<a id="comparison-baselines"></a>
### 실험 기준선과 운영 기준선

S6 비교 기준선은 R16/P0/C_FULL이고 현재 운영 기본 모델은 KI20이다. 작업 시 실제 운영 모델/adapter·코드·지시문·입력 정책·설정을 다시 확인한다. R16 대비 개선을 현재 운영 대비 개선이라고 표현하지 않는다. 직접 비교하지 않은 부분은 `not_measured`로 남기며 이를 이유로 S6 비교군을 임의로 늘리지 않는다. 별도 운영 비교가 필요하면 목적·범위·예산을 먼저 정하고 기존 S6 결과를 바꾸지 않는다.

<a id="rollout-decision"></a>
### 진단·후보 확인·운영을 구분

| 판단 | 종료 조건 |
|---|---|
| 진단 완료 | 실제 비교·제한·다음 선택 기록; 개선 없음도 결과, 필수 미실행은 완료 아님 |
| 앱 후보 확인 | 사전 정의한 경로·안전·상태 회귀 확인, CPU 모의/실제 범위 구분 |
| 미채택 | 사실·상태·개인정보 회귀, 지표 충돌 또는 근거 부족의 사유 |
| 운영 반영 검토 | 실제 후보 확인·범위·모델·입력·되돌림 경로 확정 |
| 운영 반영 완료 | 별도 승인된 전환과 실행 신원·실제 요청 확인까지 수행 |

현재 서비스·세션을 단순히 오래됐다는 이유로 종료하지 않는다. 합성 입력으로 제한 범위·정상/정정/경계/미지원·변조·동시 요청을 확인하고 실제 PID/cwd/commit/config/model이 선택 후보와 맞는지 기록한다. 인증·권한·rate limit·암호화·로그 비노출·기능 기본 off는 보존하며 활성화는 명시 설정으로만 한다. 운영 키는 공개하지 않는다.

실험 실패 때문에 검사 기준을 계속 완화하지 않는다. 반대로 미래의 모든 품질이 증명될 때까지 진단을 못 닫는 구조를 만들지 않는다. 작은 합성 확인을 전체 이용자 품질 보장으로 확대하지 않는다. Phase 6·Runtime 승인·모델 승격·서비스 전환은 서로 다른 결정이며 자동 연동하지 않는다.

<a id="rollback"></a>
### 호환 구성 단위의 되돌림

전환 전에 코드·모델/adapter·지시문 묶음·입력 정책·설정의 호환되는 조합, 복원 절차와 실패 시 복귀 기준을 고정한다. 세션/binding의 schema·revision·snapshot 호환성과 기존 대화 재개 가능 여부도 검사한다. 코드만 되돌리고 새 설정이나 호환되지 않는 binding을 남기는 복귀는 성공이 아니다. 호환성이 확인되지 않으면 전환하지 않으며 원본 세션을 변환·덮어쓰거나 무결성 검사를 우회하지 않는다.

<a id="handoff"></a>
### 최종적으로 답할 다섯 질문

1. 계산기 재개가 필요한 실제 결함/요구가 있는가, 현재 제한 범위로 충분한가?
2. 어떤 정상 요청이 앱에서 잘못 처리됐으며 후보에서 어떻게 달라졌는가?
3. P1과 큰 기본 모델은 각각 무엇을 개선하고 무엇을 해결하지 못했는가?
4. 남은 오류에는 입력·데이터·모델 규모 중 무엇을 바꾸는 것이 타당한가?
5. 유지할 후보 하나 또는 미채택 이유, 다음 최소 작업은 무엇인가?

성공은 계산기·모델·검사기의 완벽함이 아니라 병목 분리·효과가 확인된 변경 선택·근거 없는 범위 확대 방지다.

## 입력·산출물

입력은 실제 후보 검증·권한·선정 근거·승인된 전환 범위다. 산출물은 채택/미채택 결정, 제한 운영 manifest·실행 신원·합성 canary·복귀 검증 또는 기존 운영 유지 기록이다. 공개 집계와 비공개 원문을 분리한다.

## 검증

전환 전후 모델/코드 신원, 정상·경계·정정·범위 밖·변조 요청, 응답 저장/표시, 동시 process·권한·로그를 자동 검증한다. CPU 성공을 실제 모델/브라우저 성공으로, 실제 앱 성공을 의미 품질 인증으로 바꾸지 않는다. 전환 권한·실제 확인이 없으면 운영 반영 완료로 기록하지 않는다.

## 종료·중단과 다음 단계

승인된 전환·실행 확인 또는 사유 있는 미채택·기존 운영 유지로 닫는다. 문제 시 사전 정의한 복귀 절차를 따르고 계산기 확대·새 학습·모델 교체를 임의로 추가하지 않는다. 장기 기능은 새 제품 요구와 별도 계획에서 검토한다.

## 진행 기록

- 2026-09-15 보완: R16 실험 기준선과 KI20 운영 기준선을 분리하고 호환 구성·세션/binding까지 되돌림 범위를 명시했다. 운영 전환·추가 비교·되돌림 실행은 하지 않았다.

- 2026-09-15: 운영 판단과 인계 기준만 작성했다. 서비스 전환·활성화·모델 승격·복귀 실행은 하지 않았다.
