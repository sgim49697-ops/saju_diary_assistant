# 50. 자동 모델 평가와 원인 분리

이 문서는 **원인 분리 진단 상세 정본**이다. 후속 실행 순서는 [로드맵 README](README.md), 현재 Git·서비스·산출물 상태는 [00번 문서](00-current-baseline.md)가 소유한다. 이번 재정렬은 문서와 정합성 테스트만 변경한다. 아래 A~D 구현·모델 등록·다운로드·GPU 실행·데이터 생성은 후속 작업이다.

## 완료된 기준선과 미확정 가설

- 확정 [20문장](../../../SAJU_CHAT_TEST_PROMPTS.md)×K0·R16·KI20은 60요청·54생성·6사전 차단으로 완료됐다. [공개 집계](../../../data/reports/saju_1b_baseline/dashboard-prompt20/v1.0.0/build-9ab2958c83dc/aggregate.json)와 [검증](../../../data/reports/saju_1b_baseline/dashboard-prompt20/v1.0.0/build-9ab2958c83dc/verification.json)을 불변 기준선으로 사용한다.
- 연결 구조 검사 K0 8/13·R16 10/13·KI20 8/13은 정확도가 아니다. 세 모델의 잘못된 일간 전제 수용은 실제 입력 facts까지 확인한 응답 오류다. 개념 설명 오류를 놓치거나 정확한 일간 답변을 누락으로 표시하는 검사기 한계도 별개로 확인됐다.
- 첫 질문 12개 그룹 token identity 일치, 54응답 입력 재구성, 부모 이력 60요청 대조, 최대 입력 2,024 token·제외 대화 0이다. 무조건 context를 늘릴 근거는 없다.
- R16 학습 데이터 2,000행의 일반 공감 250행은 모두 원국 미연결이고, 1,751행의 답변은 비어 있지 않은 줄이 3개 이상이다. 두 문장·사주 제외 요청의 특정 문자열 검색은 각각 0건이지만 의미상 같은 예제가 없다는 증명은 아니다. 데이터 SHA·검색 조건은 [재정렬 기록](../../history/2026-09-05-model-cause-roadmap.md)에 남긴다.
- 모델 규모, 지시문, 입력 상태, 학습 분포가 각각 얼마나 영향을 줬는지는 미확정이다. 20문장은 이미 노출된 개발 진단이며 일반 성능이나 새로운 봉인 평가로 주장하지 않는다.

## 50-A. 오류 분리와 진단 계약 고정 — 다음 작업

1. 실제 모델 오류, 검사기 누락·오탐, 자동 계약으로 측정하지 못하는 설명 품질을 서로 다른 항목으로 분류한다. 일간/일주·원국/일진 역할, 틀린 전제 교정, range/unknown, 정보 정정, 일반 대화 전환, 요청한 문장 수·수정 반영을 회귀 대상으로 명시한다.
2. 기존 응답을 유리하게 덮어쓰지 않는다. 새 자동 검사에는 정답·오답·인용·부정·개념 모순의 합성 최소 회귀 사례를 함께 고정한다. 표현만 맞는 값을 개념 설명 전체의 정답으로 세지 않는다. 모호한 문장은 억지로 PASS/FAIL하지 않고 미측정으로 분리한다.
3. 질문 원문·분기 관계·원국/원국+일진/비연결 조건·KST 기준일·allowlist·실행 코드·모델 revision·지시문·tokenizer/template·decoding·상한·검사기 version을 실행 전에 고정한다. 실제 답변이 나온 뒤 목표를 조정하려면 새 version이다.
4. 완료 산출물은 원인 분류표, 재현 가능한 CPU 회귀, 다음 비교의 manifest/분모/종료 조건과 dry-run이다. 구현 전인 새 CLI나 config를 이미 존재하는 것으로 기록하지 않는다.

## 50-B. R16 지시문 단일 후보 비교

- 고정 R16의 현재 지시문과 개선 후보 **하나**만 비교한다. 개선 축은 승인 fact 우선·틀린 전제 교정, range/unknown 보존, 연결 상태에서도 일반 대화 허용, 요청한 결과물/형식 우선이다. 이번 문서에서 지시문 코드를 수정하지 않는다.
- R16 가중치·같은 입력 snapshot/형식·사용자 질문·tokenizer/template·decoding·입출력 상한은 고정하고 시스템 지시문만 바꾼다. 지시문 변화에 따른 token 수 차이는 기록하되 다른 변수까지 함께 바꾸지 않는다.
- 첫 turn은 변경한 지시문을 제외한 입력이 같아야 한다. 후속 turn은 각 arm 자신의 응답을 따른 end-to-end 결과로 분리한다. 후속 단일 지시문 효과를 주장하려면 별도 동결 부모 이력 재생이 필요하며 두 방식을 섞어 평균내지 않는다.
- 완료 조건은 항목별 개선·회귀·불변과 검사 범위 밖 한계를 기록하는 것이다. 모두 정답이어야 진단 완료인 것은 아니다. 실패 사례마다 지시문을 계속 덧붙여 이번 비교를 무한 반복하지 않는다.

## 50-C. 큰 동일 계열 Instruct 기본 모델 비교 — 필수

이 축은 선택 사항이 아닌 **필수 진단**이다. 작은 모델의 한계라는 가설을 확인하기 위해 **K0 1.3B 기본 모델 ↔ 큰 동일 계열 Instruct 기본 모델**을 비교한다. **R16 ↔ 큰 기본 모델**만으로 크기 효과를 판단하지 않는다.

1. 실행 전 후보 저장소·정확한 revision·공식 라이선스·가중치 hash·공식 tokenizer/template·지원 길이·정밀도를 등록한다. 유휴 GPU·실제 여유 VRAM·KV cache 포함 메모리 요구량·offload 여부와 실행 가능성을 확인한 뒤 별도 실행 범위를 확정한다. 특정 큰 모델은 아직 등록·다운로드하지 않았다.
2. 원칙은 동일 정밀도다. 메모리가 부족하다고 다른 계열이나 양자화 모델로 자동 대체하지 않는다. 수행 불가 사유와 필요한 조건을 기록하고 대체 설계는 별도 결정한다. 미실행을 비교 완료로 세거나 필수 축을 조용히 생략하지 않는다.
3. 사용자 질문·계산 facts·연결 상태·기준일·시스템 지시문 의미·generation 조건은 동등하게 유지한다. 50-B 결과를 본 뒤 비교 전 지시문 한 버전을 명시적으로 동결하고, 두 기본 모델에 공통 적용한다. 모델별 공식 tokenizer/template를 각각 고정하며 **서로 다른 모델의 token ID 동일성은 요구하지 않는다**. 입력 삭제·truncation 없이 둘 다 수용되는지 dry-run으로 검증한다.
4. 첫 turn과 각 모델 고유 후속 이력의 결과를 구분한다. K0·큰 기본 모델의 항목별 차이와 자원 비용을 보고하고 R16은 별도 참고 비교로만 둔다. R8/R32를 포함한 기존 5-arm 생성 비교의 미완료 상태와도 혼동하지 않는다.
5. 큰 기본 모델이 좋아도 크기만의 순수 인과 효과를 증명한 것은 아니다. 사전학습 데이터·학습량·후처리 등 잔여 교란 요인을 명시한다. 같은 계열·동일 정밀도 비교는 그 한계를 줄이는 설계이지 제거하는 설계가 아니다.

## 50-D. 학습 커버리지와 입력 전달을 분리 점검

- 50-B/C 후 남은 오류를 기준으로 실제 serving 입력에 facts/slot이 없거나 잘못 실린 경우와, 올바르게 전달됐는데 모델이 따르지 않은 경우를 나눈다. 원국 연결 중 일반 대화 전환, 잘못된 전제 교정, 시간 범위와 미상, 요청한 출력 형식의 네 축을 먼저 확인한다.
- 데이터 분석은 고정 training manifest·task axis·메시지 구조·입력 조건·assistant-token 분포를 사용한다. 문자열 빈도만으로 의미상 커버리지 부재를 단정하지 않는다. 기존 최소 3문장/3줄 계약은 당시 불변 데이터 이력이며 두 문장 요청에도 적용할 미래 규칙이 아니다.
- 별도 v1.1 보정 400건은 intake·uncertainty·HARD QA 중심이다. 이번 실패 네 축을 실제로 보완하는지 확인한 뒤 유지·범위 재설계·보류 중 하나를 기록한다. 자동 재개나 재학습을 지시하지 않고 기존 accepted 행·state는 보존한다.
- 완료 산출물은 원인별 근거·불확실성·최소 변경 후보와 반증 가능한 재검증 조건이다. 지시문만으로 해소된 축에는 데이터 확대를 요구하지 않는다. 입력 전달 오류는 앱/상태 수정으로, 남은 분포 문제는 별도 표적 데이터 제안으로 분리한다.

## 종료와 후속 경계

- A~D의 계약·실제 비교 결과·한계·다음 조치가 기록되면 진단을 닫는다. 실행하지 못한 필수 비교는 미실행으로 남긴다. **진단 완료는 품질 승인과 다르다.**
- 자동 지표는 사실 모순·허위 완료·상태 전이·기제공 필드 재질문·불필요한 입력 요구·요청 형식·max-token hit·일반 회귀를 각각 분모와 함께 보고한다. 의미 품질·자연스러움은 자동 계약이 없으면 `not_measured`이며 새 완료/승격 blocker로 삼지 않는다. 계약 밖 평가를 완료 조건으로 추가하지 않는다.
- 공개 보고서는 집계·manifest·해시·계약만 기록한다. 기존 Phase 6와 grounded-dialogue 원시 출력, 소비된 sealed blind는 열거나 재사용하지 않는다. 이미 공개된 합성 20문장 진단을 봉인 성능으로 포장하지 않는다.
- [60 데이터 build](60-mix20k-v3-1-build.md)와 [70 학습·승격](70-training-and-promotion.md)은 결과에 따른 조건부 후속이다. 진단 통과로 자동 실행하지 않는다. Phase 6·Runtime release·기본 모델·서비스는 그대로 유지한다.
