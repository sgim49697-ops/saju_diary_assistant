## 계산·앱·검사에서 확인한 제한

| 지점 | 확인한 내용 | 이번 처리 |
|---|---|---|
| 계산·상태 | 승인 adapter의 exact/range/unknown, 윤달 미확인, 생일 정정 뒤 이전 결과 무효화 | CPU 회귀로 검증, 원래 계산 코드 보존 |
| 의도/날짜 | `오늘은 사주 얘기를 쉬고 싶어…`가 일진 요청으로 분류됨 | 모델 생성 전 차단으로 별도 집계, 분류기 수정 없음 |
| 의도/날짜 | 오늘과 내일이 함께 들어간 후속 요청이 다중 날짜로 분류됨 | 실제 기존 차단 사유를 사전 등록 |
| 추론 | 원본 loader BF16, R16 adapter는 기존 PEFT loader에 따라 일부 FP32 | dtype 분포·실제 generation 인자·종료 토큰 기록, 정밀도 임의 교체 없음 |
| 출력 | API/저장 소비 함수의 격리 CPU 재생 | 원응답과 표시·저장 hash 대조, 실제 운영 브라우저 실행과 구분 |

실제 Claude Code CLI와 테스트 수정 및 코드 검토를 나눠 수행했다. 제안된 call177 fixture의 부모 hash 누락은 실제 테스트에서 추가 발견해 보완했다. 공개 manifest 전체 필드 재계산·실제 선택 P0 hash·GPU lock/부모 process 확인도 교차 검토 후 보강했다.

자동 검사기는 유한 label 문법이며 해석 품질의 정답률이 아니다. 실행 중 코드만을 대상으로 한 추가 점검에서 다음 한계를 합성 문자열로 확인했다. 동결 후 scorer를 수정하거나 불리한 결과를 교체하지 않는다.

- `일간은 丁이 결코 아니에요`처럼 부정어 사이에 부사가 있으면 긍정 주장으로 잘못 읽을 수 있다.
- `일간은 丁, 아니 사실 甲입니다`는 쉼표 뒤 label 없는 교정을 놓칠 수 있다. 실제 검사 결과는 丁만 인식해 PASS가 될 수 있었으며, 교차 검토 초안의 “두 주장을 모두 인식한다”는 추측과 구분했다.
- `태어난 날의 간지는 丁亥입니다` 같은 바꿔 말하기, `시주는 子입니다`처럼 지지 한 글자만 제시한 주장은 현재 label/value 문법에서 인식하지 못한다.
- 사실 모순 항목의 `UNSCORABLE`에는 일반 대화처럼 명시적 사실 주장이 없는 응답도 포함한다. 적용 항목·판정 가능 수·생성 수를 따로 보고하며 PASS 수를 의미 정확도라고 부르지 않는다.

### 실제 비교에서 추가 확인한 검사기 오탐

R16의 FULL→MIN `required_fact_use` 회귀 8개를 새 합성 응답과 대조했다. 그중 6개는 실제 오류 증가가 아니라 아래 검사 범위 문제였다. 따라서 **13→6 PASS를 R16 정확도 하락으로 해석하지 않는다.** 나머지 2개에는 잘못된 기둥 구성이나 정정 전 일주 사용이라는 실제 오류가 있었다. 이 점검은 기존 aggregate를 사후 재채점하거나 교체한 결과가 아니다.

| 검사 범위 문제 | 독립 합성 문자열로 확인한 잘못된 처리 |
|---|---|
| 인접 label/value 혼동 | `甲子는 일주이고 甲은 일간입니다`에서 일주=甲이라는 추가 주장을 추출 |
| 간접 부정 누락 | `일간이 을목이라고 읽히지 않고…`를 을목이라는 긍정 주장으로 추출 |
| 단정 부정 누락 | `일간이 을목이라고 단정할 수는 없습니다`를 긍정 주장으로 추출 |
| 과거/현재 범위 혼동 | 정정 전 원국의 설명과 수정된 현재 원국의 설명을 모두 현재 사실과 비교 |
| 이전 답변 인용 누락 | 앞선 잘못된 설명을 되짚고 현재 사실로 교정해도 앞선 설명을 현재 주장으로 비교 |

원인 위치는 새 진단 검사기와 여기서 재사용한 기존 `dashboard_grounding_v2`의 claim 추출 문법이다. 원응답·저장·API 출력이 달라진 문제는 아니다. 회귀 8개 밖의 PASS/FAIL은 전량 재분류하지 않았으므로 보정된 정확도나 모델 순위를 만들지 않는다. K0·KI20와 위치 대조의 같은 검사 지표도 동일한 제한을 받는다.

다음 최소 작업은 S1 검사 계약 보강이다. 새 version에서 위 문법의 양성·음성 fixture와 범위 보존을 먼저 통과시키고, 이번 private 합성 결과를 그대로 읽어 **새 파생 집계**를 만들 수 있다. 기존 build·scorer·aggregate는 보존하고 추가 GPU 생성이나 재학습은 필요하지 않다. 이 후속 구현은 이번 동결 실행에 섞지 않았으며, 이후 S3 지시문 단일 변수 비교와 S4 크기 비교의 순서를 유지한다.

### 본 비교의 동결 자동 점수

각 모델·조건은 48요청 = 43생성 + 5사전 차단이다. 필수 사실 항목의 적용 분모는 24이고 아래에 PASS/FAIL/UNSCORABLE을 모두 적는다. **검사기 오탐이 확인됐으므로 이 표로 모델 순위나 실제 정확도 차이를 주장하지 않는다.**

필수 사실의 paired FULL→MIN은 다음과 같다. 판정 불가 쌍을 제외한 분모는 K0 22, R16 23, KI20 17이다. R16의 회귀 8개 중 확인한 검사기 오탐 6개는 앞 절을 따르며 이 표를 사후 보정하지 않았다.

날짜 사용은 FULL 세 모델 모두 2/2, MIN은 K0·KI20 1/2와 R16 2/2다. 윤달 확인 요청은 K0·R16 두 조건 모두 PASS, KI20 두 조건 모두 UNSCORABLE이다. 불확실성·정정·전제 교정의 세부 분모와 층별 결과는 공개 집계를 따르며, claim 추출에 의존하는 항목에는 앞 절의 오탐 제한을 적용한다.

필수 값 변경 대조는 세 모델·두 조건 모두 출력이 바뀌었다. 관련 없는 출생 시각/도시 변경 대조의 FULL 출력도 세 모델 모두 바뀌었고, 필요한 사실만 보존해 최종 입력이 같아진 MIN 출력은 세 모델 모두 같았다. 출력 변화 자체는 사실을 올바르게 사용했다는 증거가 아니다. 적어도 K0·R16의 새 합성 응답에는 MIN에서도 잘못된 기둥·개념·정정 전 사실을 사용한 실제 오류가 남았다. 따라서 정보 삭제만으로 해결됐다고 볼 수 없지만, 검사 보강 전 정보 조건·모델의 우열도 확정하지 않는다.
