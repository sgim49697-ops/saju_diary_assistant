## 재현한 결함과 보완

| 구분 | 이전 v1.19에서 확인한 현상 | 새 v1.20 처리·회귀 |
|---|---|---|
| 일상 동음이의어 | `일간 연락드릴게요`는 원국 설명, `우리 반 일진이 누구야?`는 날짜 확인으로 오인 | 위치별 사주 필드 판별로 일반 대화 처리; 미연결/연결 모두 확인. 한 문장의 학교 일진과 실제 오늘 일진을 서로 구분 |
| 정의 요청 오차단 | `용신이라는 용어는 무슨 의미야? 나는 사실 잘 몰라서.`가 개인 계산 차단 | 절별 판별로 무관한 자기소개를 분리. `나는 용신의 뜻이 궁금해`처럼 명시적 정의의 주어도 구분하되 개인 용신·신강약 판정 요청은 계속 차단 |
| 복합 요청 소실 | `내 일간이 뭐고 성격도 알려줘.`를 직접 사실 한 줄로 종료 | 직접 응답은 닫힌 단일 조회 문법에 한정. 성격·위로·별도 문장 요청은 원문 전체와 필요한 승인 사실을 생성 경로로 전달 |

추가 프로브로 `신약 성경`·신약 개발을 명리 계산과 구분하고, 용어 설명과 현재 일간을 같이 요청할 때 승인 사실이 누락되지 않는지 확인했다. 일반 대화에서 facts를 생략해도 binding은 유지한다. 실제 HTTP→worker→저장 경로에서 질문 원문과 승인 사실·응답 종류·저장 원출력을 대조했다. 직접 사실 조회는 계속 모델을 호출하지 않는다.

첫 추가 회귀에서 `나는 사주를 처음 들어봐. 신강과 신약의 뜻을 설명해줘`의 연결/미연결 2개 subtest가 실패했다. 자기소개와 실제 추가 요청을 구분하도록 구현을 수정했으며 기대값을 완화하지 않았다. 후속 표적 테스트는 68개를 통과했다. 정규식으로 모든 한국어 의도를 증명한 것은 아니며 모델 생성 품질은 미측정이다.

마지막 변경분에 대한 Claude 검수는 주어를 지우는 예외 규칙에서 **설명과 생략된 개인 판정이 섞인 새 회귀**를 발견했다. `나는 용신의 뜻이 궁금하고 신강 여부도 알려줘`, `저는 신강의 뜻이 궁금한데 신강인지 아닌지도 알려줘`를 연결/미연결로 재현해 4개 subtest 실패를 확인했다. 제안대로 정의구를 먼저 소비하고 그 밖에 미지원 용어가 남으면 개인 주어를 유지해 차단하도록 수정했다. 이 실패와 수정을 삭제하거나 기존 기대값을 완화하지 않았으며, 미발행 상태에서 정책·테스트 identity를 함께 변경했다.

종결 검수에서 제시된 주어 없는 변형도 미확인으로 남기지 않고 3문장×연결/미연결의 6개 실패를 재현했다. `신강 여부`, `신강인지`, `신약인지`처럼 미지원 판정을 요구하는 표현은 개인 대명사가 없어도 차단하도록 작은 공통 검사를 추가했다. 순수 용어 정의·사주 제외·일상 신약 표현과 기존 직접 사실 조회 기대값은 유지했다. 새 표적 전체는 70개이며 기존 실패를 성공으로 보고하지 않는다.

후속 검수는 `인가/일까` 등 다른 어미에서도 같은 구조가 남는다고 지적했다. 8문장×연결/미연결의 16개 실패를 재현한 뒤 중간의 어미 목록 검사를 제거했다. **최종 규칙은 미지원 용어의 모든 출현이 명시적 정의구 안에 있어야 일반 설명으로 허용한다**는 것이다. 정의구를 제거한 나머지에 미지원 용어가 있으면 주어·어미에 관계없이 차단한다. 정의구 안의 지식 요청 주어만 구분하고 다른 개인 소유·계산 동사는 계속 차단한다. 여러 용어의 뜻·차이와 `격국은 무슨 의미야?` 같은 긍정 회귀도 추가해 70개를 재통과했다. 이 보완은 유한한 계약 검사이며 모든 한국어 문맥을 이해하는 분류기로 주장하지 않는다.

7차 검수는 이 구조적 보완을 확인하고, 정의 질문 뒤 무관한 옷·메뉴 선택 요청이 있으면 전체를 막는 절 간 오차단을 추가 지적했다. 4개 오차단과 `저에게 맞는 걸 알려줘`의 지시어 누락 1개를 재현했다. 무관한 개인 대명사+선택 동사를 전체 메시지의 사주 판정으로 취급하지 않고, 용어 자체의 미지원 요청과 `나에게/저에게 맞는 것`의 생략 참조를 구분했다. **이 마지막 수정은 구현 담당의 로컬 회귀·전체 테스트로 검증했으며 Claude에 다시 전달한 8차 검수는 없다.** 최종 표적 71개가 통과했다. 수정 도중 잔여 테스트 실패 1건과 그에 따른 canary 실행 실패도 발생했으며, 실행기는 공개 파일 발행 전에 중단했다. 이를 성공 기록으로 대체하지 않는다.

## S5 의견의 범위 판정

- 임의 입력을 내부 `analyze_data`에 직접 주면 미지의 대문자 문자열이 집계 key로 쓰일 수 있다는 지적은 합성 입력으로 재현했다. 그러나 현재 CLI는 config·teacher state·repair state를 고정 SHA-256으로 검사한 뒤 해석한다. 다른 입력은 거부했고, 현재 공개 집계의 key는 `CLAIM_GRAMMAR: 73`, `UNCLASSIFIED: 2`다. 현재 산출물 유출이나 통계 오류로 판단하지 않는다.
- 파일 크기 `stat` 이후 경로를 다시 읽는 경쟁은 자원 사용상의 방어 보완점이다. 뒤의 크기·고정 해시 검사 때문에 잘못된 바이트를 승인하는 우회는 확인되지 않았다. 동일 경로가 경쟁 중 대용량 파일로 교체되면 읽기 메모리가 증가할 가능성은 남는다. 이를 현재 동결 입력의 안전성 전체 증명으로 확대하지 않는다.
- Claude 재검수도 현재 S5를 수정할 근거와 향후 범용화 요구를 구분하는 데 동의했다. 기존 S5 소스·config·보고서·학습 가설은 보존한다. **다른 입력을 받는 후속 버전을 만들 때** 공개 오류 코드 allowlist와 같은 fd의 `fstat`·상한 읽기, 변조·경쟁 회귀를 먼저 반영한다. 새 Phase나 현재 완료 blocker로 추가하지 않는다.
