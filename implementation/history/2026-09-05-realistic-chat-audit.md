# 2026-09-05 학습 상태·일상 대화 진단

## 결론과 범위

R8·R16·R32 LoRA 학습은 모두 완료됐다. R16은 원국·단일 일진 구분과 일부 입력 유지에서 개선된 응답을 보였지만, 날짜 전환·시간 미상 이해·질문에 맞는 설명과 문장 작성에 실패가 남아 있다. 현재 자동 검사에도 실제 오류 누락과 정상 응답 오탐이 있으므로 통과 수를 모델 정확도로 사용하지 않는다.

- 기준: 원격 master `b78f8e630261db7a1561c649d5fadac91e321d58`.
- 활성 서비스: dashboard v1.14, loopback 8767, 원국 v1.5 + 단일 day. 실행 worktree `codex/r16-dashboard-v1-14`의 관련 코드·config는 기준 master와 같다.

- 신규 합성 질문 10개·6개 대화 흐름을 K0·R16·KI20에 전달해 HTTP 응답 30개를 생성했다. 기존 사용자 세션이나 봉인 데이터에서 표본을 뽑지 않았다.

- Phase 6, Runtime release, 모델 승격, 추가 학습 상태는 변경하지 않았다. 이번 진단은 Stage 50의 정식 5-arm 평가 완료가 아니다.

## 신규 대화 관찰

이 표는 개별 실행에서 관찰한 동작을 요약한다. 원출력·전체 질문·세션 ID는 비공개 열람본에 보존한다.

| 질문 유형 | K0·KI20에서 관찰한 문제 | R16에서 관찰한 동작 |
|---|---|---|
| 오늘 사주 | K0는 날짜 간지를 원국 월주·시주로 바꿈. KI20은 다른 연도의 날짜와 원국 label을 생성 | 원국 일주와 선택 날짜의 연간지·월간지·일진을 정확히 구분. 사실 나열 위주 |
| 쉬운 말로 행동 세 가지 | K0는 일반적인 조언, KI20은 틀린 원국 주장을 유지 | 실행 가능한 세 가지 조언을 했지만 날짜·원국 표식을 생략해 자동 경고 발생 |
| 내일·이번 주 후속 | KI20은 앞선 틀린 원국을 유지하면서 판단을 유보 | 오늘 snapshot을 내일의 흐름에 사용하고 하루 정보를 이번 주 설명에 확대. 자동 검사는 통과 |
| 원국 장점·주의점과 현실 예 | K0는 일간과 일주를 혼동. KI20은 해당 연주에 없는 원소를 주장 | 일주·일간 사실은 맞지만 그것을 장점이라고 부르고 주로 제한만 설명. 요청한 장단점 설명은 부족 |

| 생시 미상 단일 질문 | K0·KI20은 입력을 되풀이하는 짧은 답변 | 사용자가 시간 미상을 명시했는데 해당 값이 입력되지 않았다고 설명 |
| 일반 감정 대화 | 세 모델 모두 출생정보 요구 없이 응답 | 감정을 받아주지만 실수에 따른 피로 등 사용자가 말하지 않은 상황을 덧붙임 |

| 일간 확인 | K0·KI20은 맞는 일간 설명에 틀린 원국 주장을 혼합 | 원국 네 기둥과 일간을 정확히 설명했지만 날짜 사실 누락으로 자동 경고 발생 |

## 자동 지표와 재현된 검사 결함

| 모델 | 응답·nonempty | 연결 응답 중 기존 검사 통과 | 평균 생성 호출 시간 | 최대 입력 tokens | 제외 turn |
|---|---:|---:|---:|---:|---:|
| K0 | 10/10 | 0/5 | 10.578초 | 2,099 | 0 |
| R16 | 10/10 | 2/5 | 8.968초 | 1,864 | 0 |
| KI20 | 10/10 | 1/5 | 9.213초 | 1,952 | 0 |

시간은 모델 로드·검증을 포함한 각 호출의 측정치다. 표본은 작고 한 합성 원국에 집중돼 있다. `existing_gate_pass`는 아래 결함을 가진 당시 검사 결과이며 실제 정확도·사용성 점수가 아니다. 일반 대화 다섯 응답씩에는 연결 원국 Gate가 적용되지 않는다.

1. `phase5_dashboard_v1_14.py::_bound_prompt_intent`가 공백을 모두 지운 뒤 날짜 단어를 찾는다. 그 결과 `내 일간`이 `내일간`이 되어 내일 요청으로 분류된다. 같은 질문에서 `내`를 빼면 원국 질문으로 분류되는 것을 CPU 재생으로 확인했다.
2. `audit_bound_output`의 기간 label 검사는 `period.hard_facts.pillars`를 읽는다. 실제 v1.5 결과는 `period.hard_facts.period`에 `year_ganzhi/month_ganzhi/day_ganzhi`를 둔다. 정상 원국 일주와 잘못된 연간지→일진 주장을 섞은 합성 출력을 넣어도 `passed=true`가 되는 것을 재현했다.
3. `evaluate_bound_output`은 날짜·간지 표식 중 하나가 있으면 기간 근거가 있다고 판단하며, 사용자가 요청한 내일/주간 범위와 snapshot 날짜를 비교하지 않는다. 실제 R16의 날짜 확대 오류가 통과했다.
4. 원국 질문에서 네 기둥 전부를 요구하는 추가 검사와, 한자 표식 포함 여부 검사는 질문에 필요한 사실만 설명하거나 쉬운 한국어로 풀어달라는 요청에 오탐을 만들 수 있다. 실제 일간 확인 답변과 쉬운 행동 조언에서 이를 관찰했다.

검사기 테스트 fixture와 실제 Runtime 결과 schema를 함께 검증하도록 수정해야 한다. 원국/기간 fact 값의 존재와 그 값에 붙은 위치·날짜 label의 정확성은 각각 검증해야 한다.

## tokenizer 비교 조건

동일한 tokenizer 파일 hash와 `fix_mistral_regex=True`를 사용해도 실제 backend가 달랐다. 설치된 Transformers의 `_patch_mistral_regex`는 모델 config의 `transformers_version`을 분기 조건으로 사용한다. K0는 `4.57.1`인 non-Mistral config라 조기 반환하고, KI20은 `4.57.6`이라 정규식 교체를 적용한다. 이 때문에 숫자 등 일부 문자열이 서로 다르게 토큰화된다.

같은 KI20 가중치·동일한 렌더링 원문에서 기존 tokenizer와 원본 K0 tokenizer만 바꾼 두 질문×두 조건을 추가 실행했다. 기존 조건의 두 답변은 HTTP 원출력과 byte 단위로 일치했다. 입력 token은 각각 `1,771→1,679`, `1,786→1,694`로 변했다. 원본 tokenizer 조건에서도 지시문 재출력과 근거 없는 설명이 남았으므로 tokenizer 차이를 없애는 것만으로 응답 문제가 해결됐다고 판단할 수 없다.

앞선 예비 통제 4응답은 system prompt의 끝 공백 처리 방식이 serving과 달라 HTTP 비교 근거에서 제외했다. serving의 검증된 prompt loader를 사용한 정확한 통제 4응답만 위 결론에 사용했다. 모든 예비 출력도 별도로 보존했다. 생성 총량은 주 진단 30 + 정확한 통제 4 + 제외된 예비 통제 4다.

학습 효과 비교 전 tokenizer 파일뿐 아니라 로드된 backend·렌더링 결과·최종 token ID를 동결해야 한다. 후속 turn에서는 모델별 응답 이력이 달라지는 점도 분리 기록한다.

## 데이터·문서 해석

- 2K target은 1줄 249행, 3줄 1,574행, 4줄 177행이다. `일주`를 포함한 답변이 1,448/2,000행이다. 이런 사실·형식 중심 분포는 R16의 반복적 사실 나열과 관련될 가능성이 있으나 인과 효과를 확정한 결과는 아니다.
- 이번 신규 질문 10개는 training 사용자 발화와 공백 정규화 exact overlap이 0건이었다. 이것은 같은 문장 중복 검사이며 의미적 누수 부재를 증명하지 않는다.
- 입력은 모두 4,096 상한 안이고 제외 turn도 0이다. 이번 실패를 context 부족으로 설명할 근거는 없다. 긴 세션의 별도 성능은 이번에 측정하지 않았다.
- 원국 연결 prompt는 `bound_chart_v2`를 사용한다. 비연결 입력 prompt는 현재 `guided_runtime_v2`이며, 기존 2K builder의 intake prompt와 다른 후속 보정 경로다. 비연결 결과를 해석할 때 이 배포 조건 차이도 포함해야 한다.
- `saju_product_roadmap/README.md` 상단의 dashboard v1.11·추가 학습 일괄 차단 서술과 최신 LoRA 진행 기록 사이에는 시점·범위 차이가 남아 있다. 완료된 baseline Phase 6, 별도 LoRA 실험, 아직 미완료인 v1.1.0 보정을 구분해야 한다. 이번에는 그 차이를 기록했고 전체 정본 재편은 하지 않았다.
